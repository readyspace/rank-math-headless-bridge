# Prepare for the WordPress Plugin Directory

This guide explains the steps needed to list the bridge on WordPress.org. A
GitHub merge does not publish a WordPress plugin. WordPress.org reviews the ZIP
first. After approval, we upload the release to its separate SVN repository.

**Current status: name review in progress.** Version **0.2.0** was submitted on
October 11, 2026. On October 12, the WordPress.org team requested a more
distinctive name. We are preparing corrected version **0.2.1** as **ReadySpace
Headless SEO Bridge for Rank Math**. The corrected ZIP has not yet been uploaded,
and the plugin has not been approved or published.

The replacement slug is a proposal. WordPress.org decides its availability and
acceptability during review. Check it before approval, because changing an
approved plugin's slug is not normally possible.
[WordPress.org submission information](https://wordpress.org/plugins/developers/add/).

Suggested short description:

> Use Rank Math SEO on a separate Next.js website. Optional WPGraphQL support, a REST alternative and guides for headless WordPress.

Suggested explanation for the reviewer:

> This independent, GPL-3.0-or-later WordPress plugin helps a separate frontend use SEO data generated by Rank Math. Rank Math is installed separately. The main Next.js guide uses optional WPGraphQL; a separate REST route is available. All bridge modules start off. Eligible SEO output is limited to published, public, password-free posts in selected public post types. The optional IndexNow adapter changes Rank Math's submission URLs to the frontend host; Rank Math remains responsible for making the external requests. The package contains readable PHP, an uninstaller, readme, licence, changelog and credits. Setup guides and frontend examples are available in the linked GitHub repository. It does not bundle Rank Math, WPGraphQL or a deployed Next.js app.

## Check your own site before enabling features

These checks apply to each site's setup. They are separate from the directory
submission checklist and should happen on staging before changing a live site.

- [ ] Follow the setup guide on your own test copy. Save settings, deactivate
  and reactivate the bridge, and confirm the intended choices remain.
- [ ] Check the frontend page source: titles, public canonicals, search
  instructions, social previews and schema. Check that draft, private and
  password-protected pages stay out of the bridge's public output.
- [ ] If you choose IndexNow, verify the public key file and a real submission
  on a site you control before enabling that adapter on the live site. Leave it
  off until that works. Real IndexNow delivery has not been established by the
  package checks; using the optional service is not required to use or submit
  the plugin.

All bridge modules start off. WPGraphQL stays optional at the plugin level.
Rank Math with Headless CMS Support and PHP DOM is needed for the SEO APIs.
The Next.js helpers also need to be added to the frontend project.

## External services, credits and the affiliate link

The optional IndexNow adapter uses Rank Math's existing submission process.
The readme explains the destination, when notifications happen and what is sent:
public URLs, host, verification key, key-file address and Rank Math client
information, including a coded identifier based on the WordPress home address.
Submitted URLs are shared with participating search engines. The
receiving service can see the server's IP address. IndexNow's
[terms page](https://www.indexnow.org/terms) includes its website privacy section;
it does not replace each participating search engine's own policy.

The directory description and GitHub README both contain one directly linked,
clearly disclosed Rank Math affiliate link:
`https://rankmath.com/?ref=super%20salesman`. The disclosure explains that a
qualifying purchase may earn the project's owner a commission. A paid Rank Math
plan is not required to use the bridge. Rank Math is the required SEO provider,
so the link appears next to its introduction rather than as repeated promotion.
WordPress.org's [readme rule](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/#12-public-facing-pages-on-wordpress-org-readmes-must-not-spam)
allows moderate links to required products and requires direct affiliate links
with disclosure. The review team decides whether the final listing is acceptable.

The description also introduces ReadySpace as the project's developer and links
to `https://readyspace.com`. The plugin's Author URI points to the same website.
The contributor account remains `readyspace`. Using ReadySpace hosting or opening
a ReadySpace account is not required.

This plugin does not place affiliate links or credit links on visitors' pages.
Rank Math is credited as the SEO provider. The bridge is an independent project
and does not claim Rank Math's endorsement.

## Upload the corrected ZIP for the existing review

1. Sign in to the confirmed owner's WordPress.org account. Make sure the
   account's email can receive review messages.
2. Open [Add your plugin](https://wordpress.org/plugins/developers/add/).
3. Find the existing 0.2.0 submission and upload the corrected 0.2.1 ZIP through
   its review process. Check any automatic feedback before finishing.
4. Use the existing review thread to request the distinctive display name and
   replacement slug. Wait for the Plugin Review Team's response and address
   their remaining questions.

Uploading a correction continues the review; it does not publish the plugin.
The review team decides whether it meets directory rules.

## Publish after approval

SVN is WordPress.org's release storage. GitHub can remain the place where we
develop the plugin and discuss changes.

1. Use the SVN repository address supplied in the approval email.
2. Put release files directly in `trunk/`, including the main PHP file and
   `readme.txt`. Do not nest another plugin folder inside `trunk/`.
3. Copy the finished release to `tags/<RELEASE_VERSION>/`. Use the agreed stable
   number in both readmes, the PHP header and the version constant.
4. Put optional directory icons, banners and screenshots in the separate
   `assets/` folder. Use our own artwork or images we have rights to use.
5. Inspect the changes, then upload the finished release. If Release
   Confirmation is enabled, confirm it through WordPress.org's release screen.
6. Check the public listing and install it from the directory on a test site.

Upload the extracted release files to SVN, not the ZIP itself. Do not send every
GitHub commit to SVN. Use it for finished releases.
[Official SVN guide](https://developer.wordpress.org/plugins/wordpress-org/how-to-use-subversion/).
[Release Confirmation](https://developer.wordpress.org/plugins/wordpress-org/release-confirmation-emails/).
